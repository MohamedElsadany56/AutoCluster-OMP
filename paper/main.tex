\begin{abstract}
Clustering algorithms such as K-Means and Fuzzy C-Means are widely used in data science and machine learning, but their repeated distance computations become expensive as the number of points, clusters, features, and iterations increases. Manual OpenMP parallelization can reduce runtime, but it requires the programmer to identify independent loops, avoid race conditions, select suitable schedules, and validate correctness. This paper presents AutoCluster-OMP, a lightweight source-to-source automatic parallelization prototype for clustering workloads. The tool analyzes sequential C implementations of K-Means and Fuzzy C-Means, detects clustering-specific loop patterns, classifies safe and unsafe loops, generates OpenMP directives, compiles sequential/manual/auto-generated versions, and evaluates performance using runtime, speedup, efficiency, and checksum-based correctness validation. The prototype targets the K-Means assignment loop and the Fuzzy C-Means membership-update loop, while warning about shared centroid-update patterns that may introduce races. Experimental results show that auto-generated OpenMP code achieves meaningful speedup while preserving correctness. On the Covertype K-Means workload, AutoCluster-OMP achieved a 4.37$\times$ speedup at 8 threads. For Fuzzy C-Means, the auto-generated version achieved up to 5.12$\times$ speedup in the schedule and hyperparameter sweep.
\end{abstract}

\section{Introduction}

Modern processors provide multiple cores, but sequential machine learning and data mining programs often fail to utilize this hardware efficiently. Clustering algorithms are a clear example. K-Means and Fuzzy C-Means repeatedly compute distances between data points and cluster centers, and their runtime grows with the number of points, clusters, features, and iterations.

K-Means is a hard clustering algorithm, where each point is assigned to exactly one cluster. Fuzzy C-Means is a soft clustering algorithm, where each point has a membership degree for every cluster. Although the algorithms differ in their assignment semantics, both contain dominant data-parallel loops. In K-Means, the point-assignment loop can process different points independently. In Fuzzy C-Means, the membership-update loop can update membership rows independently.

OpenMP is a practical shared-memory programming model for multicore CPUs. However, inserting OpenMP directives manually requires experience. Some loops are safe to parallelize, while other loops, such as centroid-update loops, may contain shared writes and can introduce race conditions. Therefore, an automatic parallelization tool should not simply add OpenMP directives blindly. It should detect loop patterns, classify safety, and generate code only when the transformation is valid.

This project proposes AutoCluster-OMP, a lightweight source-to-source automatic parallelization prototype. The tool reads sequential C clustering code, detects supported loop patterns, generates OpenMP directives, compiles the generated code, benchmarks it against sequential and manual OpenMP baselines, and validates correctness using checksums.

The main contributions of this work are:
\begin{itemize}
    \item A lightweight source-to-source automatic parallelization prototype for clustering workloads.
    \item Automatic detection of K-Means assignment loops and Fuzzy C-Means membership-update loops.
    \item Loop-safety classification that distinguishes independent loops from unsafe centroid-update loops.
    \item OpenMP code generation with configurable scheduling policies.
    \item Experimental evaluation using runtime, speedup, efficiency, schedule comparison, and checksum-based correctness validation.
\end{itemize}

\section{Related Work}

\subsection{Parallel K-Means}

The parallelization of K-Means clustering is a central problem in high-performance data mining, focusing on partitioning the workload between distance calculations and centroid updates. While the assignment phase is embarrassingly parallel, the centroid update phase remains a primary bottleneck due to write contention caused by irregular scatter-style aggregations \cite{parallel_customer_segmentation_2025}. Recent innovations, such as Flash-KMeans, introduce contention-free implementations using sort-inverse updates to transform high-contention atomic scatters into high-throughput reductions on modern GPUs \cite{yang2026flashkmeans}. However, achieving these gains on shared-memory architectures typically requires manual pragma insertion or the use of thread-local buffers, as automated tools often fail to manage these memory dependencies \cite{parallel_customer_segmentation_2025,yang2026flashkmeans}.

The gap is that current research predominantly focuses on manual parallelization strategies that require significant programmer intervention to manage data dependencies and synchronization issues in centroid updates.

\subsection{Parallel Fuzzy C-Means}

Parallel Fuzzy C-Means introduces significantly higher computational complexity than hard clustering because each point has a membership value for each cluster. For large-scale data, research has turned to distributed frameworks such as Apache Spark, using distributed data abstractions to handle membership matrix updates across clusters \cite{spark_fuzzy_cmedian_2024}. Hybrid approaches such as FCMCAA utilize the Hadoop MapReduce framework to balance big data anonymization with parallel execution speed \cite{lawrance2024fcmcaa}. Despite these advancements for cloud-based environments, non-expert developers lack lightweight automation for local multicore systems, where the overhead of distributed clusters may outweigh the benefit of parallelization.

The gap is that there is a lack of accessible, lightweight automation tools that can recognize specific fuzzy clustering patterns on local shared-memory architectures without resorting to heavyweight distributed frameworks.

\subsection{Automatic Parallelization}

Automatic parallelization aims to transform sequential code into parallel code without human intervention. The Cetus Compiler v2.0 serves as a source-to-source infrastructure using compiler analysis and transformation techniques to insert OpenMP directives \cite{bhosale2022cetus}. To improve optimization coverage, recent research such as the Parallel-Semantics Program Dependence Graph utilizes advanced compiler foundations to capture parallel program dependencies that traditional models may miss \cite{homerding2024pspdg}. Furthermore, recent systems such as LLMA4OpenMP use large language models to assist automatic OpenMP parallelization \cite{zhu2025llma4openmp}. While these tools advance the field, they may not provide domain-specific and explainable diagnostic feedback regarding why certain irregular clustering loops are unsafe for transformation.

The gap is that general-purpose automatic parallelization tools often operate as broad compiler frameworks or black-box systems. They do not directly target clustering-specific patterns or provide simple diagnostic explanations for assignment loops, membership-update loops, centroid-update hazards, and workload-aware OpenMP insertion.

\section{Proposed Solution}

\subsection{System Overview}

AutoCluster-OMP is designed as a lightweight source-to-source transformation pipeline. The input is a sequential C implementation of a supported clustering algorithm. The output is a generated C file containing OpenMP directives for safe loops.

\begin{figure}[t]
\centering
\includegraphics[width=0.95\linewidth]{figures/pipeline.png}
\caption{AutoCluster-OMP source-to-source automatic parallelization pipeline.}
\label{fig:pipeline}
\end{figure}

The pipeline performs the following steps: read sequential C clustering code, detect C \texttt{for} loops, classify loop patterns using clustering-specific rules, check safety and workload size, insert OpenMP directives before safe loops, compile sequential/manual/auto-generated versions, benchmark performance, and validate correctness using checksums.

\subsection{Supported Patterns}

For K-Means, the target loop writes one cluster label per point:

\vspace{6pt}
\noindent\centering{\scriptsize\textbf{Listing 1. K-Means target assignment loop.}}\par
\vspace{4pt}
\begin{lstlisting}[language=C]
for (int i = 0; i < n; i++) {
    ...
    labels[i] = best_cluster;
}
\end{lstlisting}

The generated loop is:

\vspace{6pt}
\noindent\centering{\scriptsize\textbf{Listing 2. Generated OpenMP K-Means assignment loop.}}\par
\vspace{4pt}
\begin{lstlisting}[language=C]
#pragma omp parallel for schedule(static)
for (int i = 0; i < n; i++) {
    ...
    labels[i] = best_cluster;
}
\end{lstlisting}

This transformation is safe because each iteration writes to a unique \texttt{labels[i]} location, and centroids are read-only during the assignment phase.

For Fuzzy C-Means, the target loop updates membership values:

\vspace{6pt}
\noindent\centering{\scriptsize\textbf{Listing 3. Fuzzy C-Means target membership-update loop.}}\par
\vspace{4pt}
\begin{lstlisting}[language=C]
for (int i = 0; i < n; i++) {
    for (int c = 0; c < k; c++) {
        ...
        membership[i * k + c] = value;
    }
}
\end{lstlisting}

The outer loop is safe to parallelize because each point owns a distinct row in the membership matrix.

Centroid-update loops require special handling because multiple threads may update the same cluster accumulator:

\vspace{6pt}
\noindent\centering{\scriptsize\textbf{Listing 4. Unsafe shared centroid update pattern.}}\par
\vspace{4pt}
\begin{lstlisting}[language=C]
centroid_counts[cluster]++;
centroid_sums[cluster * d + f] += points[i * d + f];
\end{lstlisting}

Therefore, the prototype does not blindly parallelize these loops. It either warns about the race-condition risk or relies on manual/thread-local buffer versions for comparison.

\subsection{Workload-Aware Decision}

Small workloads may not benefit from OpenMP due to thread creation and scheduling overhead. Therefore, AutoCluster-OMP estimates computational work before parallelization. For K-Means, the estimated work is:

\begin{equation}
W_{KM} = N \times K \times D \times I,
\end{equation}

where $N$ is the number of points, $K$ is the number of clusters, $D$ is the number of features, and $I$ is the number of iterations. For Fuzzy C-Means, the membership-update step performs additional cluster-to-cluster comparisons, so the estimated work is approximated as:

\begin{equation}
W_{FCM} = N \times K^2 \times D \times I.
\end{equation}

\section{Evaluation and Results}

\subsection{Experimental Setup}

The evaluation compares sequential, manual OpenMP, and auto-generated OpenMP implementations. The experiments use synthetic Gaussian datasets and the Covertype real-world dataset. The Gaussian workload names were renamed in the paper for readability: \texttt{paper\_2d\_100000} is reported as G2D-100K, and \texttt{paper\_3d\_1000000} is reported as G3D-1M.

All C implementations were compiled with GCC using \texttt{-O2}. OpenMP versions were compiled with \texttt{-fopenmp}. The evaluated thread counts were 1, 2, 4, and 8. Correctness was validated by comparing checksums against the sequential reference.

\subsection{Metrics}

Runtime is measured in seconds. Speedup is calculated as:

\begin{equation}
S = \frac{T_{seq}}{T_{par}},
\end{equation}

where $T_{seq}$ is the sequential runtime and $T_{par}$ is the parallel runtime. Efficiency is calculated as:

\begin{equation}
E = \frac{S}{P},
\end{equation}

where $P$ is the number of OpenMP threads.

\subsection{Discussion}

The results confirm that AutoCluster-OMP can generate correct and efficient OpenMP code for both hard and soft clustering workloads. K-Means achieved strong speedup on both synthetic Gaussian workloads and the real-world Covertype dataset. Fuzzy C-Means achieved higher absolute runtimes but also strong speedups because its membership-update loop performs significantly more computation.

The one-thread OpenMP versions are sometimes slower than the sequential baselines. This is expected because OpenMP introduces runtime overhead even when only one thread is used. However, as the number of threads increases, the generated OpenMP versions show clear runtime reductions.

Efficiency decreases at higher thread counts. This behavior is expected in shared-memory parallel programs because of OpenMP overhead, memory bandwidth limitations, synchronization costs, and remaining sequential sections such as centroid updates and initialization. Nevertheless, the speedup results show that the dominant assignment and membership-update loops are suitable targets for automatic parallelization.

\section{Conclusion and Future Work}

This paper presented AutoCluster-OMP, a lightweight source-to-source OpenMP auto-parallelizer for clustering workloads. The prototype detects K-Means assignment loops and Fuzzy C-Means membership-update loops, generates OpenMP directives, benchmarks the generated code, and validates correctness using checksums. Experimental results show that auto-generated OpenMP code can achieve meaningful speedup while preserving correctness. On Covertype, auto-generated K-Means achieved 4.37$\times$ speedup at 8 threads. On Fuzzy C-Means, the auto-generated implementation achieved 4.32$\times$ speedup on the 10K-15C-20F workload and up to 5.12$\times$ in the schedule sweep.

Future work includes replacing the pattern-based parser with Clang AST analysis, improving automatic centroid-update transformations, adding automatic OpenMP schedule selection, supporting additional clustering algorithms, and extending the generator to OpenACC or CUDA for GPU execution.
